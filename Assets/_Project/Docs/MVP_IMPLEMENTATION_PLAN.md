# PRIDE COURT（仮称）MVP 実装計画書

更新日: 2026-08-13
対象: Unity 6000.5.4f1 / PC / Android

## 1. 目的

動物・ロボット・ファンタジー種族が、世界の命運と種族の誇りを懸けて戦う3Dカードアクションテニスを制作する。MVPでは、1対1のプレイヤー対CPU戦を最後まで遊べる状態を完成条件とする。

最初から完成アセットを作り込まず、仮素材でテニスの移動・返球・照準・スタミナ・カード判断が面白いことを確認してから、セルシェーディングとフィギュア調の外観へ置換する。

## 2. MVP完成条件

- PCとAndroidで起動できる。
- 1コート、2キャラクターから選択できる。
- プレイヤー対CPUの1対1を開始・終了できる。
- 6ポイント先取、5対5以降は2点差、サーブ権は1ポイントごとに交代する。
- 1st/2ndサーブ、10秒制限、フォルトが機能する。
- A（強）とB（弱）、方向入力による球種・5段階照準が機能する。
- 歩行、ダッシュ、ダイブ、打点補正、スタミナ、疲労が機能する。
- 16枚デッキ、手札3枚、ポイントごとのドロー、カード使用と捨て札循環が機能する。
- 共通カード8種類、ルクス／バスティオン専用カード各2種類が機能する。
- キャラクターごとの次球発動型必殺技が機能する。
- EASY / NORMAL / HARD のCPUが同じルールと可視情報で戦う。
- HUDの表示、サイズ変更、PC/Android別保存が機能する。

## 3. MVP対象外

- オンライン通信の実装
- 2対2およびローカル4人対戦
- カード収集、アンロック、課金
- ランキング、リプレイ、観戦
- 最終品質のキャラクター、背景、音声

ただし、試合状態・入力・表示・CPUを分離し、将来の通信同期と2対2で中核ルールを書き換えない構成にする。

## 4. 確定ルール

### 4.1 試合

- 6ポイント先取。5対5以降は2点差がつくまで継続。
- サーブ権は1ポイントごとに交代。
- ポイント終了時にスタミナを全回復し、疲労状態を解除。
- 必殺技ゲージはポイント間で保持し、試合終了時にリセット。

### 4.2 入力とショット

- ショットボタンを押した瞬間の方向で球種を固定する。
- その後、インパクト直前までは方向入力を照準として扱う。
- 照準は中央、左右の浅角度、左右の深角度の5ゾーン。
- アナログとAndroidは角度ゾーンへ吸着させる。
- キーボードは左右入力の保持時間で浅角度から深角度へ遷移させる。
- タイミングはジャスト、通常、早い／遅いの3段階。範囲内ならミス入力でも甘い球として原則返球する。
- 通常球には着弾予測を表示しない。ロブには早い段階から着弾サークルを両者へ表示する。

### 4.3 移動とスタミナ

- PCはShift、ゲームパッドとAndroidはスティックの傾きでダッシュ。
- PCはSpace＋WASDでダイブ。ゲームパッドとAndroidは一度ニュートラルへ戻し、0.28秒以内に同じ方向へ強く再入力するとダイブ。
- ダイブ返球はB相当の安全球。A入力時は追加スタミナで少し速く返す。
- ダイブ成功後は短い硬直、空振り後は長い硬直。
- スタミナ最大100。暫定値は歩行回復8/秒、静止回復14/秒、ダッシュ15/秒、Aショット12、ダイブ25、ダイブA追加10。
- 消費後0.4秒は自然回復を停止。
- 0で疲労状態となり、移動速度70%、Aは安全球へ変換。80まで回復すると解除。

### 4.4 サーブ

- サーブ権を得て操作可能になった時点から打球するまで10秒。ラケットに当たった時点でカウントを停止する。
- ベースライン上の正規範囲で左右移動可能。トスした瞬間に足位置固定。
- A/Bショットボタンの初回入力で固定高トスし、再入力したAでトップスピン、Bでスライス（Spaceはキーボード補助入力として維持）。
- トスの見送りは時間内なら何度でも可能。時間切れは1フォルト。
- 1stフォルト後は10秒へ戻して2ndサーブ。2ndフォルトは相手得点。
- ネットに触れて正しいサービスエリアへ入った場合は、そのままラリー続行。
- サーブ打球後は両選手の通常移動、ダッシュ、ダイブを解禁する。
- レシーバーはサーブをノーバウンドでも返球できる。返球した場合は、その時点でラリー成立として扱う。
- カードと必殺技は、正しいサービスバウンドまたはノーバウンド返球によってラリーが成立するまで使用できない。

### 4.5 カード

- 通常デッキ16枚、同名最大3枚、専用カードは1種類最大2枚。
- 試合開始時に5枚引き3枚を選択。残り2枚を山札へ戻して再シャッフル。
- ポイント開始時、両者が1枚ドローし、15秒の整理時間で手札3枚を確定。
- 不採用カードと交換元は捨て札へ送る。山札が尽きたら捨て札を再シャッフル。
- 有効なラリーが1回以上あり、そのポイントでカード未使用かつ専用カードを保持していない場合、次回整理時に専用山札から1枚引く。
- 専用山札は専用2種類を各2枚。使い切ったら専用捨て札を再シャッフル。
- 長押し＋方向選択＋解放でアクティブカードをセット。短押しで使用。
- 個人強化同士、コート効果同士は最後に使った1枚だけ有効。異なる対象の効果は併存可能。
- 数秒効果とラリー中効果はポイント終了時に解除。

### 4.6 必殺技

- キャラクターごとに1種類、ゲージ100%で使用可能。
- ボタンで予約、再入力で解除。次の有効打球で全消費し、空振りでは消費しない。
- A/Bで必殺効果自体は変わらず、Aは強く、Bは安全な打球になる。
- 必殺球を返球すると通常球へ戻る。ジャスト返球はゲージ15～20%を獲得する暫定値。
- 予約中にポイントが終了した場合は予約だけ解除し、ゲージを保持。
- 1～2秒のカットイン中は全操作、ボール、CPU、スタミナ、効果時間を停止。
- 演出終了後は約0.3秒のスローを挟み、通常速度で全員同時に操作再開。
- 同じ能力へ作用するカード効果とは最後に発動した補正を優先し、無関係な効果は併存。

## 5. 初期コンテンツ

### 5.1 ルクス

俊敏なキツネ族。高い加速・旋回・スタミナ効率、低めのパワーと安定性。

- 必殺技「ミラージュバウンド」: バウンド後に軌道が変化する。着弾予告は表示しないが、固有フォームと軌跡で必殺球であることを示す。
- 「フラッシュステップ」: 5秒間、加速・旋回・減速を30%強化。
- 「テイルフェイント」: 次のBショットの回転量を35%強化し、着弾誤差を軽減。

### 5.2 バスティオン

大型競技ロボット。高パワー、広い打球範囲、安定姿勢。加速・旋回・減速は遅め。

- 必殺技「グラビティドライブ」: 返球した相手のスタミナを追加で削る。返球は有効となり、その後に疲労を適用。
- 「レールブースト」: 5秒間、直線最高速度20%上昇、ダッシュ消費25%軽減。
- 「アンカーコア」: 6秒間、Aショット消費50%軽減、悪い打点による威力低下を緩和。

### 5.3 共通カード

アクセルステップ、エコラン、リカバリーパルス、スピンブースト、ゲージチャージ、グリップコート、スリップコート、ハイバウンド。

## 6. アーキテクチャ

SOLIDを優先し、以下を分離する。

- `Domain`: Unity表示に依存しない試合ルール、得点、スタミナ、ゲージ、デッキ状態。
- `Input`: キーボード／マウス、ゲームパッド、Androidを共通コマンドへ変換。
- `Gameplay`: 選手、ボール、コート、サーブ、ショット解決。
- `Cards`: カード定義と効果適用。効果追加時に試合中核を変更しない。
- `AI`: 可視状態から意思決定し、プレイヤー入力を直接参照しない。
- `Presentation`: HUD、カメラ、演出、音。ゲーム状態を書き換えない。
- `Editor`: 仮コート生成、検証、コンテンツ構築。

データはScriptableObject化できる境界を用意するが、MVP初期に不要な汎用フレームワークや通信層の実装は行わない。

- 画面状態は`PrideCourtFrontEndFlow`、表示と既存試合への接続は`MvpFrontEndController`が担当する。将来のマルチ実装は各入口の遷移先を置き換え、タイトル表示へ通信責務を追加しない。
- PCはEnter、数字1／2、Escapeを補助操作に使える。AndroidはSafe Area内の大きなボタンをタップする。

完了条件:

- `Opening → Title → ModeSelect → Setup`でソロ対CPU戦を開始できる。
- `ModeSelect → MultiplayerSelect → LocalNetworkLobby`のみ選択できる。`OnlineNetworkLobby`のコードは再開用に保持するが、画面操作と内部遷移からは到達不能にする。
- 戻る操作で各通信ロビーから`MultiplayerSelect → ModeSelect → Title`を逆順にたどれる。
- 静的検証で全状態遷移、Editor Play Modeで実際のフロントエンド制御経路とソロ試合開始を確認する。

### 2026-08-22 ローカル通信対戦（PC／Androidクロスプレイ）

#### 完成仕様

- 対象は同一LAN／同一Wi-Fi内の1対1。片方がホスト、もう片方がゲストとして参加する。
- LAN検索はUDPブロードキャスト、試合通信は遅延を抑えたTCP接続を使用する。外部サーバー、アカウント、クラウドサービスは不要。
- 自動検索で見つからない端末向けに、ホスト画面へIPv4を表示し、ゲスト側にIPv4直接入力を用意する。
- ホストを唯一のルール／物理判定権威とする。ゲストは`TennisCommand`だけを送信し、得点、フェーズ、ボール、両選手、スタミナ、必殺ゲージ、手札、カード獲得状態をホストから受信する。
- ゲスト側はFar選手をローカル選手として扱い、カメラ、スコア、スタミナ、手札をFar視点へ反転する。ホストは従来のNear視点を維持する。
- Windowsのキーボード／マウス／ゲームパッドとAndroidの仮想スティック／タッチボタンを、同じ`TennisCommand`通信形式で送る。
- インターネット越しの「NETWORK BATTLE」はEOS Connect／Lobby／P2Pのコードを保持するが、契約確認のため保留中。画面には`※実装前`と表示し、選択および内部遷移を無効化する。LAN通信とは`IBattleTransport`境界で分離し、再開時も試合プロトコルだけを共用する。

#### SOLID分割

- `LanDiscoveryService`: LAN内ホスト発見だけを担当。
- `LanPeerConnection`: 長さ付きパケットの送受信と切断検知だけを担当。
- `LanBattleProtocol`: バージョン、コマンド、ハンドシェイク、試合スナップショットの直列化だけを担当。
- `LanBattleSessionController`: ホスト／ゲスト状態と既存ゲームへの接続だけを担当。
- `RemoteCommandSource`: 既存`ITennisCommandSource`へ遠隔入力を注入し、選手ロジックを通信実装から独立させる。
- `LanMatchState`群: 通信に必要な状態契約をDomain層へ置き、ソケット詳細をGameplay層へ持ち込まない。

#### 同期と表示

- ゲスト入力は30Hz、ホスト状態は30Hzで送信する。TCPの`NoDelay`を有効にし、LAN内の小パケット遅延を抑える。
- ゲスト表示は受信位置へ補間し、30Hz受信の段差を描画フレーム側で緩和する。
- サーブ、ラリー、ダイブ、カード即時発動、ポイント間のカード交換／破棄、必殺技予約を共通コマンドに含める。
- 通信切断、アプリ一時停止、プロトコル不一致、ポート競合をエラー表示し、試合をセットアップ状態へ安全に戻す。

#### 受け入れ条件

1. 静的コンパイルが通り、`TennisCommand`と16枚デッキの通信往復検証が通る。
2. 1台のPCでホスト／ゲスト2プロセスを起動し、発見、接続、両者の移動、双方サーブ、返球、得点、カード、再戦、切断を確認する。
3. Windowsホスト＋Androidゲスト、Androidホスト＋Windowsゲストの両方向で同じ操作遷移を確認する。
4. Androidでは同一Wi-Fi、Safe Area、タッチ所有領域、バックグラウンド復帰、画面回転固定を確認する。
5. Wi-Fi分離／ゲストネットワーク等でブロードキャストが遮断される環境ではIPv4直接参加を確認する。

静的検証、1台内の2プロセス確認、物理Android端末のクロスプレイ確認は別々に記録し、前者だけで実機合格とはしない。
